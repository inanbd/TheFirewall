TheFirewall **1.0.5** adds a **Ports** page: open, close or restrict ports with one click, open them only during set hours or for a while, and see every port programs listen on and whether other computers can reach it.

## New

- **Ports page.** Each port you manage is **Open**, **Only some** or **Closed**:
  - **Open:** anyone may connect. Bans and blocked countries still apply.
  - **Only some:** only the addresses and countries you choose may connect. For example, Remote Desktop only from your office.
  - **Closed:** everyone is blocked.

  Closing or restricting a port never blocks addresses on your whitelist or your local network. Because it can cut off a remote session, TheFirewall asks before it does it.
- **Schedules.** Open a port only during set hours on chosen days, for example Mon–Fri 08:00–18:00, and keep it closed at other times. Or use **Open for…** to open it to everyone for 30 minutes up to a day; it closes again by itself. The service updates the firewall rules within seconds of each change.
- **Listening on this computer.** A list of every TCP and UDP port a program listens on. Each entry shows:
  - the program, its Windows service and the account it runs as;
  - whether other computers can reach the port, worked out from Windows Firewall's rules;
  - **Close** and **Manage…** buttons.
- **Common ports** buttons: Remote Desktop, SSH, SQL Server, web server, FTP, file sharing (SMB), WinRM, MySQL and PostgreSQL.
- **New commands:**
  - `TheFirewall.Service.exe ports` lists listening ports and who can reach them.
  - `export-settings <file>` and `import-settings <file>` copy all settings from one server to another.

Whether a port can be reached is worked out from the Windows Firewall rules on this computer. A router or cloud firewall in front of the server can still block it.

## Upgrading

- **Installer:** run `TheFirewall-1.0.5-x64.msi`; it upgrades 1.0.x in place. Settings, bans and history are kept.
- **Portable:**
  1. Close the tray icon (right-click → **Exit (protection keeps running)**).
  2. Run `TheFirewall.Service.exe stop` as administrator from your current folder, so its files can be replaced.
  3. Extract the new zip over that folder and open `TheFirewall.exe`. It starts the service again.
