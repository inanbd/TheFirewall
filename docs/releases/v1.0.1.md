TheFirewall **1.0.1** makes sure protection is always running: the app now starts the background service on its own, including the portable version.

## What's new

- **The app always starts the service.** Each time `TheFirewall.exe` opens:
  - **Not installed** (e.g. the portable version): it installs the service from its own folder and starts it. Windows asks for administrator permission once; after that the service starts automatically with Windows.
  - **Stopped:** it starts it, without a permission prompt.
  - **Points to a moved or deleted copy:** it repairs the service to use the current folder.
  - **Permission declined or something fails:** a notification and a **Start service** button on the dashboard tell you protection is off.
- **`TheFirewall.exe --ensure-service`** does the same from a script and exits (exit code 0 = running).
- **More robust service setup:** `TheFirewall.Service.exe install` repairs an existing service. A new `configure` command (also run by the installer) sets automatic start and restart-after-failure, and lets signed-in users start the service.
- **Fixed:** monitors for software that isn't installed (for example VisualSVN) were shown as "Watching". They now show "Not installed here".

## Tested on Windows

Every build now runs an end-to-end test on a real Windows machine:
1. The app installs and starts the service.
2. The app starts it again after it's stopped.
3. Simulated attackers, written to a log file and to the Windows event log, are banned in a Windows Firewall rule.
4. Uninstalling removes the service and every rule.

**Requirements:** Windows 10 1809+ or Windows Server 2019+ (x64), with Windows Defender Firewall turned on. The .NET runtime is included.

The installer is not code-signed yet. Windows SmartScreen may warn about it; choose **More info → Run anyway**, and compare the checksum with `SHA256SUMS.txt` if you like.

**Upgrading a portable copy:** close the tray icon and extract the new zip over the old folder (or into a new folder). Open `TheFirewall.exe`; if the service still uses the old folder, restart it with `TheFirewall.Service.exe install` from an elevated prompt.
