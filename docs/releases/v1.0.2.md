TheFirewall **1.0.2** fixes the "You can look around, but changing settings needs administrator permission" banner. In earlier versions it stayed even after restarting the app as administrator. The app also now always runs as administrator.

## Fixes

- **Administrators can change settings again.** The service failed to verify who the app was, so every app was treated as read-only, even elevated ones. CI now checks on every build that an administrator can make changes and a standard user is read-only.
- **"Failed-logon auditing could not be enabled (auditpol exit code 1314)"** appeared when `TheFirewall.Service.exe` ran as an ordinary program instead of as the Windows service. That can't happen by accident any more (see below), and the warning now explains what to do.

## Changes

- **The app always opens as administrator.** Windows asks for permission when you open it. The tray icon started at sign-in needs no prompt. The sign-in tray task now runs for administrators only.
- **Double-clicking `TheFirewall.Service.exe` installs or starts the Windows service** instead of running it as an ordinary program. Use `--console` to run it in the foreground for troubleshooting.
- **Only one service process can run at a time.** A second copy exits with a clear message in the service log.
- **New `TheFirewall.Service.exe check`** shows whether the service is reachable and whether you may change settings.

## Upgrading

- **Installer:** run `TheFirewall-1.0.2-x64.msi`; it upgrades 1.0.x in place.
- **Portable:**
  1. Close the tray icon and any `TheFirewall.Service.exe` window you started by hand.
  2. If an older portable copy's service is still installed, run `TheFirewall.Service.exe uninstall` as administrator from that old folder.
  3. Extract the new zip and open `TheFirewall.exe`. It installs and starts the service.
