TheFirewall **1.0.4** fixes **Install service** doing nothing in a portable copy extracted from a downloaded zip.

## Fixes

- **The portable app installs the service again.** Windows marks files extracted from a downloaded zip as coming from the internet. The app started the service tool through the Windows shell without a window, so the shell could not show its security prompt and cancelled the launch. The app read that as a declined administrator prompt and showed nothing, so the service stayed uninstalled. The app now starts the tool directly. CI checks this on every build with files marked as downloaded.
- **Errors are shown.** If installing or starting the service fails, the app now shows the tool's actual error message instead of a generic one or nothing at all.

## Changes

- Every attempt to install or start the service, and the tool's output, is written to `%LOCALAPPDATA%\TheFirewall\app.log`.
- New screenshots in the README.

## Upgrading

- **Installer:** run `TheFirewall-1.0.4-x64.msi`; it upgrades 1.0.x in place. Settings, bans and history are kept.
- **Portable, service not installed** (for example after "Install service" did nothing in 1.0.3): extract the new zip and open `TheFirewall.exe`. It installs and starts the service.
- **Portable, service running:**
  1. Close the tray icon (right-click → **Exit (protection keeps running)**).
  2. Run `TheFirewall.Service.exe stop` as administrator from your current folder, so its files can be replaced.
  3. Extract the new zip over that folder and open `TheFirewall.exe`. It starts the service again.
